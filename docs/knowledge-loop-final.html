知識迴圈：小 PR 累積、release 驗收

三元組：reviewer 對 code 的理解（蒸餾原料）＋作者回饋（逐字入帳）＋ PR 終態（裁決）。核准權從每條小 PR 撤走，收攏到你們本來就有的儀式—— release → master 的驗收 PR；週期內知識即時可用，落地一週期一批。新增服務數 0。

Phase A — 週期內

每條小 PR（→ release/*），重複 N 次
A1小 PR review 完成code+llm

v2 pipeline 照常出報告。K 段從這裡分岔、非同步起跑——不擋使用者。

K1閘門（確定性）code

目標分支 ∈ KNOWLEDGE_BRANCHES（release/*）才進； 純 version-bump／分支同步 merge 出局、revert 必收； 驗收 PR 本身（release/* → master）豁免——它是儀式，不是知識單元。

K2蒸餾 + 貼稿llm

distiller 吃現成產物（PR 文字＋review 報告＋graph 鄰接），憲法：never invent intent—— why 缺席就標記、順手在稿末問作者一行 why（記憶最新鮮的時刻）。 稿貼成 PR 留言（KNOWLEDGE_POST）——不催核准，理不理都行。

K3小 PR 終態分類 → 暫存code
作者有回覆staged/explicit — 回覆逐字收進 Author note
沉默 + code 未再動staged/silent — 原稿照單暫存
回覆含 reject丟
draft 之後又有 pushstale 丟（稿已不描述合併物）
PR abandoned丟（從未發生的決策不入帳本）
completed → staged（silent，等週期驗收）
↻ 暫存即生效：同週期後續的 review，loader 連 _cycle/ 暫存稿一起讀 （主鍵＋graph 的 affected 鄰接副鍵），注入時標 staged, pending cycle acceptance—— 飛輪在週期內就轉，不等收口。

Phase B — 收口

每 1–2 週一次：release → master 驗收 PR
B1驗收窗開啟code

harvester 偵測到 active 的驗收 PR → 貼一則 cycle digest：本週期全部暫存條目 （實體、來源 PR、provenance、一句摘要）。這就是階段性驗收的介面。

repo-a: digest → 驗收 PR#500（3 條開窗）
B2團隊掃一眼（唯一的人工時刻）人

release 當天本來就在做整體驗收的那個人，順眼掃 digest； 不同意哪條就回 reject <EntityName>（任何人可回）——該條當場出局。其餘不用動。

B3驗收 PR completed → 批次落地code

倖存條目寫進實體頁（provenance：cycle/explicit｜cycle/silent、 History blame 疊行）＋自動生成 _cycles/<日期>-PR<id>.md 週期收據。 驗收 PR 若 abandoned → 暫存原地保留、等下一輪。digest 與收口皆冪等。

repo-a: 驗收 PR#500 收口 → 落地 3 條 + 週期頁
↻ 收口之後，所有 review 讀的就是正式頁（主鍵＋affected 副鍵命中）； 報告 Coverage 表記 Knowledge context | N entries injected —— 引用率的量測點。

Provenance（信任等級攤在陽光下）

explicit＝作者說過話；silent＝沉默合併照單；staged＝週期內暫行； unreviewed＝沒經過 bot 就進 release 的漏網 PR（watermark 補帳本行， release 史零遺漏）。條目每句話掛 PR / file:line —— 無連結的句子不得出現。
